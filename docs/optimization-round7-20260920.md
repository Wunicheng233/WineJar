# 第七轮：规划采样的等价优化与回退边界修复

日期：2026-09-20。范围为已跑通的上料路径规划；三相机定位和避障继续暂停。

## 环节、问题与方法

**优化环节：密集 IK 采样中的笛卡尔插值。** 原来每个采样点都调用通用插值函数，
重复进行端点数组转换、形状检查、位置差和最短姿态角差计算。
同一段路径的端点固定，本轮将两种差值移到段开头，只计算一次；
每个采样点直接进行原顺序的乘法与加法，再进入原来的 IK 链。

修改位置：`xarm_sdk_control/trajectory_speed_planner.py::_sample_segment`。

采样密度、IK 调用数量和顺序、前一采样点作为参考角的机制、连续性检查、速度及加速度
约束、最多三次密集尝试以及端点回退策略均保持原样。没有跨尝试缓存 IK 结果，
也没有删除控制器检查。已有记录指出求解器可能切换分支，不能假设同输入重试必然同输出。

## 离线性能与等价性验证

取历史完整上料的四条路径几何和请求速度/加速度，使用同一个确定性的线性模拟 IK，
比较本轮前源码快照与新代码。每个案例先预热，再做 **51 次交错顺序测量**。

| 路径几何 | 本地流程：优化前 → 后 | 减少 | IK 调用数：前/后 |
|---|---:|---:|---:|
| 白纸 | 1.833 → 1.422 ms | 22.4% | 118 / 118 |
| 陶瓷 | 1.764 → 1.377 ms | 21.9% | 108 / 108 |
| 第一片竹壳 | 1.877 → 1.456 ms | 22.4% | 120 / 120 |
| 第二片竹壳 | 2.126 → 1.626 ms | 23.5% | 143 / 143 |

这里的本地流程包含模拟 IK 和规划结果转字典，**不含真实控制器 IK、网络通信或控制器预检查**。
每条路径仅减少约 **0.39～0.50 ms**，不能称为真实规划提速 22%，更不能据此宣称解决了
历史 5～7 s 的长等待。

回放假设明确记录在 JSON：第一条路径起点采用末条路径的回零目标，后续起点采用前条路径
终点；模拟初始关节角为起始位姿乘 0.01，模拟关节限值为 180 deg/s、1000 deg/s²，
利用率 0.35。这些用于控制变量对比，**不是真实机器人运动学或实机轨迹复原**。

共 10 类案例，包括四条历史几何、跨 ±180° 插值、IK 接口失败、非有限角度、分支突跳、
纯姿态路径、最低速度拒绝。逐项核验：

- 密集规划的每次 IK 位姿、参考角、选项、调用次序完全一致。
- 支持的路径输出每个规划字段严格相同，失败案例的异常信息和停止位置相同。
- 支持的端点回退输出及请求严格相同；下述原本不支持的零平移案例作为刻意修复单列。
- 单元测试另对 100 组随机路径和 3 组角度/距离边界，以六关节、七关节配置各验证一次，
  共 206 组采样对照，逐点关节样本与原通用插值链完全相同。

完整数据：[基准 JSON](benchmarks/trajectory-round7-20260920.json)。

## 同时修复的边界问题

基准检查发现：密集规划已拒绝平移小于 `1e-6 mm` 的路径，因为当前速度模型不能处理
只有姿态变化的运动；但端点回退没有相同检查，会在计算关节导数时除以零。
这样，原本被密集规划拒绝的输入仍可能进入回退速度计算。

本轮在端点求解 IK 前加入与密集规划一致的距离检查，明确抛出 `TrajectoryPlanningError`。
对本次四条正常上料路径结果无影响。不支持的纯姿态/零平移路径现在在回退阶段也拒绝，
不调用 IK、不进入控制器预检查。外层正常任务错误处理仍负责中止。

这是一项输入边界修复，不是新增姿态运动能力，也不是新的避障功能。
本轮没有改动端点回退的其他估算方法。

## 是否还应继续优化

还有空间，但当前已验证的等价改进主要是毫秒级，本轮不再通过猜测修改 IK 重试或运动参数。
下一项优先工作是按第四、五轮的方案补 **3～5 次原参数、原 FP32 的完整流程数据**，
保留失败与重试，读取规划诊断及第六轮新增采图诊断。

- 规划：区分 IK 调用、密集尝试/回退和控制器预检查的耗时。
- 采图：区分取帧等待、相机恢复、对齐和保存。
- 整体：比较成功率、重试次数和完整周期，避免只比较最快成功的一次。

实验前仍需明确全局相机、吸盘/TCP 和料台相对上次上料是否移动过。本轮没有操作硬件。
秒级瓶颈有了实际数据后，再决定是否调整求解策略；目前不能给出实机收益承诺。
