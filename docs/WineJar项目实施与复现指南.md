# WineJar 酒坛视觉上料项目实施与复现指南

> 文档版本：2026-08-31
> 对应代码：`main` 分支，提交 `71b89de` 之后的实机控制实现
> 适用范围：实验室复现、设备交接、工厂现场迁移与后续工程化开发

## 1. 文档目的与当前边界

WineJar 是一套“固定全局 RGB-D 相机 + 开放词汇视觉 + 六轴机械臂 + 自制真空末端”的酒坛口物料上料系统。它的目标不是只演示一次抓取，而是把物料识别、坐标转换、吸附确认、失败恢复、运动安全和运行记录组织成可复用的闭环。

当前实机已跑通的主流程为：

1. 荷叶由人工预先铺在固定酒坛口；
2. 视觉识别白纸并放置到荷叶上；
3. 视觉识别陶瓷片并放置到白纸上；
4. 白纸和陶瓷片移走后，重新识别料台上的两片竹壳；
5. 依次把两片竹壳放到陶瓷片上，并按补偿后的角度交叉；
6. 每一片物料的吸附均由真空压力开关确认，失败后在有限次数内重新定位并换点重试；
7. 任务结束后撤离并关闭气泵、切换到放气状态。

最新保留的完整实机记录位于：

```text
xarm_sdk_control/data/complete_loading/20260830_175757_904/
```

该记录中白纸、陶瓷片、两片竹壳均在第一次尝试中通过压力确认。记录的总时长约 `81.3 s`，其中含一次 RealSense USB 自动重连和一次保守的轨迹规划退化，不应直接视为稳定生产节拍。

当前尚未稳定解决“从料台吸取折叠荷叶”：荷叶面积大、形变和展开明显，单靠当前双吸盘及离散压力开关难以保证离台。因此本版本的生产入口默认使用 `--skip-lotus`，将荷叶视为已预铺物料。这个限制必须在对外说明和现场 SOP 中明确写出。

仿真动画不在本仓库维护，位于 [Winejar-mujoco](https://github.com/Wunicheng233/Winejar-mujoco)。本指南仅覆盖实机控制、视觉和现场迁移。

## 2. 一页式复现路线

首次接手项目时，不要直接运行完整任务。建议严格按下面顺序推进：

1. 创建控制与视觉两个 Conda 环境，确认 CUDA、RealSense、xArm 网络连通；
2. 确认末端 TCP、IO 极性、压力开关极性和弹簧行程；
3. 固定相机、机械臂底座、酒坛夹具和料台后，做全局相机外参标定；
4. 用陶瓷片做视觉位置偏差测量，得到实际 TCP 中心的经验补偿；
5. 分别完成陶瓷片、白纸、竹壳的单物料吸起与放回测试；
6. 完成双竹壳交叉放置；
7. 最后运行“白纸 -> 陶瓷片 -> 两片竹壳”的完整流程；
8. 收集重复试验的成功率、节拍、偏差和失败原因，再决定是否提高速度或调整阈值。

下图概括运行时的数据和控制流：

```text
RealSense D435i
  RGB + 对齐深度
        |
        v
GroundingDINO 文本检测 ----> SAM2 掩码
        |                        |
        +------ 物料类别、置信度、掩码中心、深度 ------+
                                                       v
                       相机坐标点 p_C  -- 外参 --> 机器人基坐标 p_B
                                                       |
                                     共享视觉偏差 + 材料专属偏差
                                                       |
                                                       v
                    路径构建 -> 工作空间/相机避让 -> IK/速度预检
                                                       |
                                                       v
                                       xArm Cartesian motion + CO0/CO1
                                                       |
                              CI0 真空压力开关 <-------+
                                      成功：继续；失败：放气、回退、重扫、换点
```

这里有两个不同层次的“位置修正”，不能混为一谈：

- **全局相机外参**：`base_T_camera`，描述相机坐标系和机器人基坐标系的刚体关系。相机、机器人底座或料台的相对位置一变，就需要重新标定。
- **视觉位置偏差**：`bias_base_mm`，是外参、深度、掩码中心、TCP 实物中心等残余误差的经验补偿。它适合修正稳定、近似平移的系统误差；不能代替相机发生明显旋转或位移后的重新标定。

## 3. 当前参考硬件与接口抽象

本节记录当前实验室基线，不意味着工厂必须购买相同型号。真正应复用的是接口层、标定流程、状态机和参数验证方式。

| 子系统 | 当前参考配置 | 软件中的抽象 | 迁移时必须确认的内容 |
|---|---|---|---|
| 机器人 | UFACTORY xArm6，Python SDK `1.18.4` | `robot_motion.py` 与 xArm SDK | 基坐标、TCP API、姿态约定、关节极限、工作空间、错误码和安全机制 |
| 全局相机 | Intel RealSense D435i，固定俯视 | `realsense_capture.py` | 内参、分辨率、深度尺度、安装刚度、视野、深度有效率 |
| 视觉 | GroundingDINO Tiny + SAM2 Hiera Tiny | `vision/` 独立环境和 Unix socket 服务 | GPU/CUDA、模型版本、文本提示词、阈值、目标类别和现场背景 |
| 末端 | 单弹簧双吸盘 | `end_effector_config.py`、`vacuum_control.py` | TCP、吸盘间距、最大压缩、真空管路、实际可吸物料 |
| 真空执行 | 气泵 + 两位三通电磁阀 | `VacuumController` | 输出极性、断电状态、阀门逻辑、泵能力、泄压时间 |
| 吸附确认 | ZSE30A-01-N 压力开关，接 CI0 | `SuctionSensor` | NPN/PNP、输入电平、设定阈值、响应时间、线缆与抗干扰 |

### 3.1 当前 IO 约定

当前原型是自制真空回路，不调用 UFACTORY 原厂 `set_vacuum_gripper()`。代码直接控制控制箱通用数字输出：

| 状态 | CO0：气泵 | CO1：电磁阀 | 用途 |
|---|---:|---:|---|
| 安全空闲 / 释放 | `0` | `0` | 气泵关闭，电磁阀切到放气 |
| 接近待吸 | `0` | `1` | 先把气路切至真空通路，尚未启动气泵 |
| 吸取与搬运 | `1` | `1` | 真空通路打开，气泵工作 |
| 释放后 | `0` | `0` | 关闭气泵并放气 |

当前压力开关接在 `CI0`，硬件实测为：`CI0 = 0` 表示达到吸附阈值。软件要求该电平连续保持 `50 ms`，且必须在 `2.0 s` 内出现，才认定本次吸附成功。

这组极性必须在每次改线、换继电器、换阀或换传感器后重新验证。错误的极性会造成“看似开了真空、实际在放气”或“把未吸住误判为成功”，属于高风险问题。

### 3.2 当前末端几何

文件 [`xarm_sdk_control/config/end_effector.yaml`](../xarm_sdk_control/config/end_effector.yaml) 是当前末端的唯一配置源。

| 参数 | 当前值 | 含义与选择依据 |
|---|---:|---|
| `tcp_offset_mm_deg` | `[0, 0, 113, 0, 0, 0]` | 双吸盘工作面中心相对法兰 TCP 的轴向偏移。实测双吸盘中点与法兰中心轴基本对齐，因此 XY 为零。所有视觉对齐、接触高度与避障都依赖它。 |
| `max_compression_mm` | `20 mm` | 弹簧允许的最大压缩行程。所有任务会拒绝超过该值的下压参数，避免刚性顶压、过载或吸盘损坏。 |
| `default_compression_mm` | `13 mm` | 双竹壳任务的起始参考值。它并非万能值，白纸、陶瓷片和竹壳分别使用自己的实测下压量。 |
| `home_pose_mm_deg` | `[215.194, -2.409, 300, 178.467, 0.581, -0.014]` | 复位和相机避让姿态。当前配置将 TCP 保持在相机下方安全高度边界，便于直接进入料区。 |

更换吸盘、法兰转接件、弹簧或机械臂后，首先重测 TCP 和最大压缩行程；在这两项未确认前，不应运行任何接触任务。

## 5. 环境配置

### 5.1 操作系统与硬件前提

当前环境为 Ubuntu 24.04。至少需要：

- 可访问 xArm 控制箱的有线网络；
- RealSense 可被 Linux 识别，且用户有 USB 设备访问权限；
- NVIDIA GPU、可用 CUDA 驱动和足够显存以运行 GroundingDINO + SAM2；
- Conda；
- xArm 在 UFactory 中已解除急停、正确上电；
- 机械臂周围有人值守，急停可随时触及。

### 5.2 创建控制环境

在仓库根目录执行：

```bash
conda env create -f xarm_sdk_control/environment.yml
conda activate winejar-xarm-sdk
```

控制环境包含 Python 3.11、`xarm-python-sdk`、`pyrealsense2`、OpenCV、NumPy、PyYAML 和 pytest。它故意不放 PyTorch/SAM2，避免机器人 SDK 与深度学习依赖互相污染。

基本自检：

```bash
python -c "import xarm, pyrealsense2, cv2, numpy; print('control environment OK')"
```

### 5.3 创建视觉环境

```bash
conda env create -f vision/environment.yml
conda activate winejar-vision
pip install -r vision/requirements-sam2.txt
```

验证 CUDA：

```bash
python - <<'PY'
import torch
print('torch:', torch.__version__)
print('cuda available:', torch.cuda.is_available())
if torch.cuda.is_available():
    print('device:', torch.cuda.get_device_name(0))
PY
```

首次执行视觉脚本时，Transformers/SAM2 可能下载模型。模型权重应放在本机 `vision/models/` 或 Hugging Face 缓存中，不能提交到 Git。确认模型已经缓存后，建议生产/演示环境使用：

```bash
HF_HUB_OFFLINE=1
```

这样模型缺失会立即报错，而不会在现场因网络问题临时下载。

### 5.4 启动常驻视觉服务

另开一个终端：

```bash
cd /home/wunicheng/Git/WineJar
conda activate winejar-vision
HF_HUB_OFFLINE=1 python -u vision/scripts/03_grounded_sam2_service.py
```

启动完成后应看到 `"status": "ready"`。服务监听本机 Unix socket：

```text
/tmp/winejar_grounded_sam2.sock
```

**“模型常驻显存”** 的含义是：GroundingDINO 和 SAM2 只在服务启动时加载一次，并一直驻留在 GPU 显存中；后续每次机械臂请求视觉时，只处理新帧，不再重复加载权重。它显著减少第二次及后续扫描的冷启动时间，代价是服务运行期间持续占用显存。该服务只读取帧目录、写视觉结果，绝不连接或控制机械臂。

正式节拍测试使用 `--require-vision-service`：如果 socket 或服务异常，任务立即失败，而不会悄悄退回到耗时很长的一次性推理。

## 6. 坐标系、标定与位置补偿

### 6.1 坐标约定

系统中至少涉及以下坐标系：

| 符号 | 含义 | 单位 |
|---|---|---|
| `C` | RealSense 彩色相机坐标系。对齐深度沿彩色图像像素反投影。 | m |
| `B` | 机器人基坐标系。所有任务路径和配置教点最终都在此坐标系。 | m / mm |
| `F` | 机械臂法兰坐标系。 | mm / deg |
| `T` | 吸盘工作面中心 TCP。软件通过 `set_tcp_offset()` 设定。 | mm / deg |
| `J` | 固定酒坛口中心教点，保存于 `jar_position.yaml`。 | mm |

视觉得到相机点 `p_C` 后，使用标定矩阵转换：

```text
[p_B, 1]^T = base_T_camera · [p_C, 1]^T
p_command = p_B + bias_shared + bias_material
```

其中 `bias_shared` 是 `visual_position_bias.json` 中的经验补偿，`bias_material` 目前仅对陶瓷片存在额外 X 补偿。所有内部几何换算以米计算，送给 xArm 的 Cartesian 位姿以毫米和角度表示；不要混用单位。

### 6.2 当前标定基线

当前参考外参文件：

```text
xarm_sdk_control/calibration/global_camera_20260714_153728.json
```

它来自 12 个分布在工作区的点对，质量指标为：

| 指标 | 当前结果 | 软件门限 |
|---|---:|---:|
| 样本数 | 12 | 无硬编码最小值；现场建议不少于 12 个分散点 |
| 平均残差 | `3.41 mm` | 供评估使用 |
| 最大残差 | `6.11 mm` | 任务加载时要求不大于 `15 mm` |
| 残差标准差 | `1.61 mm` | 供评估使用 |

该文件仍可作为当前实验室配置的运行外参，但为了控制仓库体积，标定时的历史 RGB-D 样本没有随代码保留；无法仅靠该 JSON 重新求解旧外参。任何新现场都应采集自己的样本并建立新的版本化标定文件。

### 6.3 固定全局相机外参标定流程

标定是 eye-to-hand（固定相机）标定：相机固定，移动 TCP/标记点到多个已知的机器人基坐标位置，并在图像中点击同一个物理点。

1. 固定相机支架、机器人底座、料台和标定标记；
2. 在 UFactory 中手动把 TCP（或明确偏移后的标记）移动到工作区内 12 个以上、覆盖高度和 XY 范围的点；
3. 每个点运行采集脚本，左键点击图中与 TCP 对应的物理点，按 `S` 保存；
4. 深度 MAD 过大、边缘反光、遮挡或点位集中时不要保存；
5. 求解外参，检查残差；
6. 在不同位置做独立验证，不要只验证参与求解的样本。

采集命令：

```bash
conda activate winejar-xarm-sdk
python xarm_sdk_control/scripts/11_collect_global_camera_sample.py \
  --serial 014122072372 \
  --output-root xarm_sdk_control/data/global_camera_samples_site_a
```

该脚本只读机器人 TCP，不使能也不发送机械臂运动；机械臂应由 UFactory 手动移动。当前采集默认值：`640x480 @ 30 fps`、预热 30 帧、像素邻域半径 `4 px`、同深度层容差 `8 mm`、最大深度 MAD `4 mm`。这些数值的目的分别是降低帧抖动、避免把背景深度混入物体表面，并拒绝局部不稳定的深度点。

若点击的是一个相对 TCP 有偏移的标记而非 TCP 原点，必须填写 `--tcp-marker-offset-mm x,y,z`；否则求解出的外参会把标记误当作 TCP，产生稳定但隐蔽的系统偏差。

求解命令：

```bash
python xarm_sdk_control/scripts/12_solve_global_camera_calibration.py \
  --samples-root xarm_sdk_control/data/global_camera_samples_site_a
```

默认将结果写入 `xarm_sdk_control/calibration/global_camera_<timestamp>.json`。残差明显异常时，可重复传入 `--exclude <样本目录或sample.json>` 排除确认有问题的样本；不要为了让数值好看而无依据地删点，应先检查点击点、深度质量和 TCP 记录。

### 6.4 什么时候重新标定，什么时候只改偏差

| 现场变化 | 正确动作 | 原因 |
|---|---|---|
| 相机支架移动、旋转、松动或重新安装 | 重新采集外参，再测偏差 | 相机到基坐标的旋转/平移关系已经改变；单一 XY 偏移不能修正旋转误差。 |
| 机器人底座、料台或夹具相对相机移动 | 重新外参标定，或建立新的工位坐标体系 | 物理几何关系改变。 |
| 换了法兰转接件、吸盘或 TCP | 更新 TCP 后重新测视觉偏差；视实际几何再复验外参 | 相机没有动，但视觉目标对应的工具中心变了。 |
| 识别中心稳定偏向同一方向数毫米 | 测量并更新经验偏差 | 这是适合 bias 修正的稳定平移残差。 |
| 某一物料总是偏一个方向，其他物料正常 | 使用受限的材料专属补偿，并记录原因 | 可能是颜色、反光、掩码中心或物料几何造成的类别偏差。 |
| 偏差随工作区位置明显变化 | 先查外参和深度，不要堆叠多个 bias | 位置相关误差通常不是单一平移能解决。 |

### 6.5 人工视觉偏差测量

使用陶瓷片或竹壳中心作为目标，让机器人悬停在视觉预测位置上方，人工以小步距把**吸盘工作面中心**对齐目标中心，保存差值。脚本把多个样本的中位数保存为 `bias_base_mm`，并记录样本范围。

示例：

```bash
conda activate winejar-xarm-sdk
python xarm_sdk_control/scripts/18_calibrate_visual_position_bias.py \
  --run --target ceramic --use-existing-bias \
  --serial 014122072372 \
  --min-x-mm 180 --max-x-mm 520 \
  --min-y-mm -250 --max-y-mm 180 \
  --min-z-mm -85 --max-z-mm 500
```

交互命令为 `x+`、`x-`、`y+`、`y-`、`step N`、`save`、`cancel`。默认步距 `2 mm`，标定接近速度 `20 mm/s`，加速度 `100 mm/s²`。这几个低速值用于人工观察和尺量，不适合生产节拍。

只检查位置、不写入结果时使用：


## 7. 视觉模块说明

### 7.1 视觉任务的步骤

每次扫描执行以下步骤：

1. RealSense 保存一帧彩色图和与彩色图对齐的原始深度图；
2. GroundingDINO 根据文本提示词输出候选框和分数；
3. SAM2 对候选框生成掩码；
4. 根据掩码和深度提取物体表面三维点；
5. 利用 `base_T_camera` 转换到机器人基坐标；
6. 按物料类别、分数、图像边缘完整性和料区几何规则选择目标；
7. 叠加共享和材料专属偏差，送入路径规划。

保存的每一帧目录通常包含：

```text

depth_raw.png             # 16-bit 原始深度，不能按普通灰度图解释
depth_preview.png         # 仅用于人眼检查的伪彩预览
frame.json                # 相机内参、深度比例、有效深度率、设备信息
vision_result.json        # 检测类别、分数、框、掩码、三维点
annotated.png             # 人工复核用标注图
mask_*.png                # 分割掩码
```

单帧采集命令：

```bash
conda activate winejar-xarm-sdk
python xarm_sdk_control/scripts/13_capture_realsense_frame.py \
  --serial 014122072372
```

离线视觉验证命令：

### 7.2 文本提示词和物料选择

当前任务使用明确的单类别提示词，而不是把所有物料堆在同一个提示里：

| 阶段 | 提示词 | 选择规则 |
|---|---|---|
| 白纸 | `white paper.` | 选择最高分、未触边的 `paper` 检测 |
| 陶瓷片 | `ceramic disk.` | 选择最高分、未触边的 `ceramic` 检测 |
| 竹壳 | `bamboo leaf.` | 选择位于固定料区、长宽比足够大且边缘条件满足的 `bamboo` 检测 |
| 荷叶原型 | `lotus leaf.` | 仅保留在单物测试或研究中；不属于当前完整生产入口 |

不能仅凭类别标签就抓取竹壳，因为荷叶与竹壳都有类似的细长叶片外观。完整任务额外使用固定料区和外接框长宽比约束，以避免把坛口荷叶或边角误判成竹壳。

### 7.3 置信度阈值的正确使用

阈值是候选检测过滤条件，不等于“抓取成功概率”。提高阈值会减少误抓，但可能漏掉被白纸遮挡或反光的目标；降低阈值会提高召回，却可能把荷叶、桌面纹理或半截目标当作竹壳。

当前完整任务的基线：

| 参数 | 当前值 | 为什么这样设定 | 变更建议 |
|---|---:|---|---|
| 一般物料 `--min-score` | `0.35` | 白纸和陶瓷片在当前光照下有较稳定的检测；比早期 `0.45` 更能容忍实际遮挡。 | 新背景或光照下需做标注图复核，不能只看是否“有框”。 |
| 第二次竹壳扫描 | `0.10` | 上层竹壳被取走后，剩余竹壳可能只露出部分，允许较低分。 | 只能配合“靠近原料堆”的空间约束使用；不要全画面放宽至 `0.10`。 |
| 竹壳扫描 | `0.20` | 在固定料区内兼顾遮挡情况下的召回和误检控制。 | 若提高/降低，应同时检查 ROI、长宽比和误抓率。 |
| 离线视觉 `text-threshold` | `0.15` | 当前任务在 `run_vision()` 中固定传入，用于文本匹配门限。 | 作为模型调参，不应与任务层 `min-score` 混淆。 |

### 7.4 竹壳料区和边缘截断规则

当前实验室中，完整任务默认只从以下机器人基坐标料区选择竹壳：

```text
X = [400, 540] mm
Y = [50, 180] mm
外接框最小长宽比 = 2.2
```

`--allow-validated-clipped-leaf` 允许一种已在实验室确认的特殊情况：竹壳只在其主轴方向触及图像边缘，但仍可被识别为完整、可吸取的料件。这个开关不应在新工位开箱即用；工厂部署应优先让物料完全处于相机视野内，并对边缘物料设为拒绝抓取或送料修正。

## 8. 运动规划、姿态和安全策略

### 8.1 单次吸放路径

对于每一片物料，路径不是简单的“先上下再左右”，而是按运动语义分段：

1. 从复位位姿或上一任务结束位姿，直接移动到物料上方；空载水平段可同步插值到拾取姿态；
2. 慢速下降到预接触高度；
3. 以接触速度压缩吸盘弹簧，随后启动气泵并等待真空确认；
4. 小幅精确抬升，避免刚吸住时的突加速度；
5. 垂直抬到运输高度；
6. 载荷状态下移动到酒坛口上方，同时插值到目标放置角；
7. 慢速降至堆叠层高度并放气；
8. 慢速撤离。中间任务默认停留在酒坛上方而不是每片都回零，最后一片才安全复位。

这种设计有两个目的：接触和释放阶段保持稳定；空载和高处运输阶段减少冗余动作。竹壳的绕 Z 目标旋转放在水平运输段完成，而不是“边起升边旋转”，以减少两片柔性竹壳彼此缠绕的风险。

### 8.2 顶置相机避让约束

当前顶置相机下方的禁入规则硬编码在 [`xarm_sdk_control/robot_motion.py`](../xarm_sdk_control/robot_motion.py)：

```text
当 TCP 的 X > 300 mm 时，TCP 的 Z 不能 > 300 mm。
安全运输走廊高度：Z = 280 mm。
```

路径不仅检查关键点，也检查任意相邻 Cartesian 段是否穿过这一禁区。相机安装位置、机械臂基坐标或末端长度变化后，必须重新推导这个几何禁区；绝不能仅改一个高度数字然后假设安全。

### 8.3 当前完整任务的稳定优先速度剖面

完整任务 `21_complete_loading.py` 使用下表默认值：

| 类别 | 参数 | 当前值 | 选择原因与调整方向 |
|---|---|---:|---|
| 空载远距离 | `transit_speed` | `250 mm/s` | 用于空载直接接近、回位。可提升节拍，但先检查每条路径的关节速度与相机避让。 |
| 载荷远距离 | `loaded_transit_speed` | `180 mm/s` | 竹壳、白纸易滑移，低于空载速度以减少加速度冲击。吸附裕度提高后可逐步上调。 |
| 空载竖直 | `vertical_speed` | `170 mm/s` | 兼顾料区和相机下的垂直移动。 |
| 载荷竖直 | `loaded_vertical_speed` | `100 mm/s` | 防止刚吸住物料时脱落、摆动或展开。 |
| 精确段 | `precision_speed` | `50 mm/s` | 预接触、撤离等需要位置稳定的短段。 |
| 接触段 | `contact_speed` | `15 mm/s` | 在弹簧行程中安全压紧吸盘，避免电机电流突增和物料顶移。 |
| 空载加速度 | `acc` | `400 mm/s²` | 空载可较快加减速。 |
| 载荷加速度 | `loaded_acc` | `200 mm/s²` | 减小真空载荷的惯性冲击。 |
| 精确加速度 | `precision_acc` | `160 mm/s²` | 平衡靠近阶段的稳定性和停顿。 |
| 轨迹混合半径 | `blend_radius_mm` | `10 mm` | 仅允许无接触的安全连接段平滑过渡；接触、吸附、释放均精确停止。 |

程序还设有严格的任务层上限：空载/载荷运输 `400 mm/s`，空载/载荷竖直 `250 mm/s`，精确段 `60 mm/s`，接触段 `20 mm/s`，对应加速度上限为 `500/350/200 mm/s²`。这些不是机械臂铭牌限值，而是本项目针对当前末端、相机和柔性物料设定的二级上限。新机器人必须以其厂商实际关节速度、关节加速度、负载和安全规范重新建立上限。

### 8.4 关节约束感知的速度规划

命令给出的 Cartesian 速度不等于每个关节都安全。`trajectory_speed_planner.py` 会沿每个路径段以 `10 mm` 平移、`2 deg` 旋转的分辨率采样 IK，估计连续关节变化，并按关节速度/加速度利用率缩放任务速度。

当前默认利用率为：

```text
joint_velocity_utilization = 0.35
joint_acceleration_utilization = 0.35
```

它们表示只使用规划器读取到的关节能力的一部分，为分支跳变、模型误差和控制器内部插补留出余量。`--minimum-planned-speed-mm-s 3` 是一条保守下限：若规划器估算某段只能低于 `3 mm/s`，会拒绝该路线而不是以不可预测的极低速度执行。

控制器 `only_check` 的 `C24` 预检结果目前记录为警告而非硬失败，这是因为当前 xArm 在部分已实机验证的连续路径上会出现“预检 C24、实际路径完成”的保守误报。**这不是允许忽略真实限速问题的理由。** 更换机器人、末端、速度或路线后，应重新评估并尽可能将可解释的预检规则恢复为阻断条件；任何真正的运动命令返回非零、急停、状态停止或目标未到达，仍会立即中止任务。

## 9. 吸附、确认与重试策略

### 9.1 为什么需要压力确认

气泵启动并不能证明物料被吸起来：可能没有接触、吸盘漏气、物料翘曲、竹壳裂纹、吸盘打滑或物料仍搭在料台上。当前压力开关能确认“真空达到设定阈值”，是比固定延时更强的信号，但它仍不能判断：

- 物料是否彻底离开料台；
- 柔性物料是否会在运输中展开；
- 吸附点是否接近边缘并将要滑脱；
- 堆叠物料是否只吸起了上层的一部分。

因此，压力确认应与合理的机械路径、单物测试、必要的视觉复核和现场失败统计一起使用。

### 9.2 当前确认策略

| 环节 | 当前行为 | 原因 |
|---|---|---|
| 接近源物料前 | CO1 先置真空通路，CO0 关闭 | 防止下降后才切换气路造成额外延迟或放气。 |
| 压缩到接触位 | 启动气泵，等待 `0.9 s` | 给当前泵、管路和吸盘建立真空的时间。 |
| 初次确认 | CI0 在 `2.0 s` 内连续 `50 ms` 为 0 | 过滤瞬态抖动和电磁干扰。 |
| 失败 | 放气、回退至源料上方、重新扫描、换小偏移点 | 不重复压同一处无效密封点。 |
| 重试次数 | 每种物料最多 3 次 | 限制无休止尝试，同时覆盖附近小范围密封差异。 |
| 重试偏移 | `(0,0)` -> `(0,-5)` -> `(+5,0) mm` | 小范围寻找更平整、密封更好的吸附点。 |

当前白纸是一个经过现场验证的例外：白纸边缘可能稳定漏气，初次吸附确认仍然必须通过；但搬运过程中首次压力掉失仅记录告警，后续同一条白纸路径不再反复轮询。陶瓷片和竹壳则在载荷段继续严格确认。换纸张、换吸盘或调压力阈值后，这条例外必须重新验证，不应默认继承。

### 9.3 下压量不是“越大越好”

路径的接触高度可近似理解为：

```text
Z_contact = Z_visual_surface - compression_mm
```

下压量受弹簧行程约束，实际对应的是“吸盘相对表面的压缩量”，不是机器人刚性撞击量。太小会接触不足、真空泄漏；太大可能使物料顶移、造成电机电流突增、压坏脆性物料或超过弹簧行程。

当前完整流程的材料专属下压量：

| 物料 | 当前值 | 选择理由 | 新现场如何重测 |
|---|---:|---|---|
| 荷叶 | `2 mm` | 只保留为原型参数；当前完整流程通常跳过荷叶抓取。 | 单独研究，不要把此值用于量产。 |
| 白纸 | `17 mm` | 白纸放在竹壳上，表面高度和漏气情况使其需要较大但仍在 20 mm 弹簧行程内的压紧量。 | 从较小值开始，以压力确认、纸张位移和电流为判据逐步增加。 |
| 陶瓷片 | `7 mm` | 陶瓷片较硬、表面平整，不需要过大的压缩；过深会导致顶压风险。 | 以吸盘压紧、无明显负载突增、可稳定抬起为准。 |
| 竹壳 | `13 mm` | 柔性/曲面物料需要更强密封，双吸盘实机验证可吸起。 | 随含水率、弯曲度、吸盘材料和真空泵改变，需要重新实验。 |

任何情况下都不得超过当前 `20 mm` 最大弹簧行程。若工艺确实需要更大压紧量，应先更换或重新设计末端，而不是绕过软件检查。

## 10. 当前完整任务的工艺参数

### 10.1 酒坛、层高和放置角

当前酒坛口固定教点位于：

```text
X = 300 mm, Y = -200 mm, Z = 65 mm
```

配置文件：[`xarm_sdk_control/config/jar_position.yaml`](../xarm_sdk_control/config/jar_position.yaml)。若酒坛采用输送线移动而不是刚性夹具固定，应以工位定位装置、编码器或每坛视觉定位替代这个常量教点。

放置高度按累积层厚计算：

| 层 | 当前厚度参数 | 放置前已累计高度 | 说明 |
|---|---:|---:|---|
| 荷叶 | `4.0 mm` | `0.0 mm` | 当前预铺，保留高度模型。 |
| 白纸 | `0.5 mm` | `4.0 mm` | 白纸压缩后实际高度可能小于名义值。 |
| 陶瓷片 | `5.0 mm` | `4.5 mm` | 需与实际陶瓷厚度一致。 |
| 第一片竹壳 | `3.0 mm` | `9.5 mm` | 近似堆叠高度。 |
| 第二片竹壳 | `3.0 mm` | `12.5 mm` | `--second-layer-height-mm` 单独暴露便于微调。 |

这些层高不是视觉检测值，而是工艺模型。若白纸、陶瓷片或竹壳厚度变化，尤其是换供应商后，应实测“放置后稳定表面高度”，以免后续释放高度偏高或碰撞。

两片竹壳的目标角当前为：

```text
第一片：+45 deg
第二片：-60 deg
```

理论上两片约交叉垂直，但柔性竹壳与吸盘间会发生转动滑移，因此第二片使用 `-60 deg` 作为当前材料的经验补偿。更换吸盘、竹壳含水率、接触表面或运输加速度后，角补偿很可能改变。不要把“命令角”误写成“物料最终角”；应以放置后的实际主轴角度为验收依据。

### 10.2 当前完整流程的空间参数

| 参数 | 当前值 | 用途 | 调小的风险 | 调大的风险 |
|---|---:|---|---|---|
| `transport_clearance_mm` | `100 mm` | 源与坛口之间的运输高度余量 | 可能扫到料堆、夹具或前序物料 | 节拍变慢，且可能进入相机禁区。 |
| `approach_clearance_mm` | `25 mm` | 物料上方安全接近高度 | 视觉/深度小误差可能造成擦碰 | 路径变长、节拍变慢。 |
| `precontact_clearance_mm` | `5 mm` | 从预接触到压缩前的慢速段 | 太小使快速段离表面太近 | 太大增加精确慢速距离。 |
| `precision_lift_mm` | `20 mm` | 刚确认吸附后的低冲击抬升 | 可能带着物料仍接近料台就加速 | 稍增节拍；但能改善刚吸住时的稳定性。 |
| `release_clearance_mm` | `0 mm` | 相对目标层表面的放气高度 | 悬空释放导致落偏或展开 | 若为负/过小会压住下层物料；当前代码和工艺应避免负值。 |

### 10.3 当前材料专属位置补偿

共享视觉偏差为：

```text
[-5, +44, 0] mm
```

陶瓷片在完整任务中额外叠加：

```text
ceramic_pick_offset_x_mm = +8 mm
```

因此当前陶瓷片相对“原始相机转换结果”的合成 X/Y 修正为约：

```text
[+3, +44] mm
```

陶瓷专属 `+8 mm X` 是当前实物检测/吸附中心的经验修正，不应扩大成全局偏差，也不要复制到白纸或竹壳。工厂现场最好把每个物料的“视觉中心 - 实际最佳吸点”单独记录，并用足够的重复样本确认它是否真的是稳定偏差。

## 13. 工厂迁移与落地建议

### 13.1 不变的框架与必须重建的现场参数

下列逻辑可以随系统迁移：视觉请求接口、RGB-D 结果格式、坐标转换链、真空状态机、CI0 去抖确认、失败恢复框架、结果 JSON、时间线、单元测试结构。

下列内容必须为每个新工位建立版本化配置：机器人 IP 与 SDK 适配、TCP、相机外参、相机禁区、工作空间、坛口基准、物料料区、各物料吸点/压缩/层高/角补偿、压力阈值与逻辑极性、速度和加速度。

建议的现场配置目录策略：

```text
xarm_sdk_control/config/sites/
  site_a_lab/
    robot.yaml
    end_effector.yaml
    jar_position.yaml
    visual_position_bias.json
  factory_line_01/
    robot.yaml
    end_effector.yaml
    jar_position.yaml
    visual_position_bias.json
xarm_sdk_control/calibration/
  factory_line_01_global_camera_YYYYMMDD.json
```

当前代码仍使用单套 `config/`，所以真正切换工位前应先通过配置加载层或部署脚本明确选择工位目录，而不是靠人工覆盖文件。这样才能从运行结果追溯“是哪套相机、哪只吸盘、哪组阈值完成了该批任务”。

### 13.2 新机器人适配

xArm6 的 SDK 逻辑不应被默认为所有机械臂通用。迁移到其他品牌或型号时，应优先写一个小的机器人适配层，提供以下能力：

```text
connect / disconnect
set_tcp_offset
read TCP pose and joint positions
enable / clear fault / set operating mode
Cartesian move with speed, acceleration, wait and blend semantics
digital output / digital input
IK and joint-limit query，或等价的轨迹可行性检查
emergency stop and fault state query
```

然后让 `cross_place_route.py` 等纯几何模块继续输出标准位姿和运动语义。不要把新厂商 API 散落到任务脚本中，否则每次换机器人都会同时破坏视觉、重试和安全逻辑。

### 13.3 新相机或新光照适配

更换相机时要重新做：内参读取、分辨率/深度尺度确认、外参标定、视野覆盖、目标全入画检查、视觉阈值验证。即使仍是 D435i，不同安装高度和角度也意味着新标定。

现场光照变化、酒坛反光、白纸亮度、竹壳干湿状态都会影响 GroundingDINO/SAM2。建议每个物料在“最亮、最暗、反光、遮挡、相邻物料干扰”条件下保存一组 RGB-D 和 `annotated.png`，建立小型回归数据集。模型阈值的调整应以这一数据集的误抓/漏检统计为依据。

### 13.4 真空系统工程化建议

当前压力开关比纯时间等待可靠，但还是二值信号。工厂化建议逐步补强：

1. 使用连续真空传感器或至少记录压力开关达到阈值的建立时间；
2. 在关键搬运段持续记录真空状态，建立“吸附劣化”告警；
3. 为易泄漏物料设计吸盘直径、硬度、双吸盘间距和支撑方式，而不是只增加下压；
4. 用料盒、压板或限位治具约束柔性荷叶和竹壳，减少由视觉/吸盘单独承担的形变问题；
5. 将泵、阀、压力传感器和控制柜 IO 的故障状态纳入 PLC/安全回路；
6. 明确断电后的安全状态：当前方案默认泵停、阀放气，适合避免悬挂物料长期保持，但需结合现场风险评审。

### 13.5 荷叶的独立课题

荷叶失败不是简单调大吸力能解决：折叠荷叶被吸起后会展开，几何包络迅速变大，边缘可能仍搭在料台上；干燥荷叶有裂纹又会漏气。当前建议是把荷叶上料从主流程拆开验证，优先考虑料盒约束、预折叠夹具、辅助支撑、多个分区吸盘、机械夹持或吸取后先做受控翻转/竖直运输。未验证前不要把荷叶吸取放回生产主流程。

## 14. 运行记录、数据管理与复现证据

每个任务会在对应 `xarm_sdk_control/data/<task>/<timestamp>/` 下创建独立目录。成功任务写 `result.json`，失败任务写 `failure.json`；它们包含错误信息、机械臂快照、已完成阶段、时间线和必要的任务上下文。视觉扫描目录保留 RGB-D、掩码和标注图。

`TaskTimeline` 使用单调时钟，区分“程序启动”和“productive_cycle_started”。比较节拍时必须统一口径：

- 是否计入视觉服务冷启动；
- 是否计入机器人复位；
- 是否计入相机重连；
- 是否计入录像；
- 是否计入人工摆料、确认和恢复；
- 是否只统计第一帧开始到最终撤离的生产周期。

建议每次重要试验至少归档：Git commit、现场配置快照、标定文件、命令行、物料批次/湿度描述、成功/失败、每段时间线、关键截图或视频。原始大量 RGB-D 可按保留策略清理，但不能删除与一次合格验证对应的最小证据集。

配置和标定文件属于生产资产，不是普通实验垃圾：

- 可以清理：大量临时 `data/` 目录、可再生成的模型缓存副本、失败调试截图；
- 必须版本控制：`config/*.yaml`、`config/*.json`、`calibration/*.json`、任务脚本、测试和本指南；
- 推送前检查：不要提交模型权重、超大视频、传感器隐私数据或未经脱敏的现场图像。

## 15. 验收、可靠性与节拍测试建议

当前项目已经证明了“完整流程可以跑通”，但尚未完成量产级可靠性验证。建议按以下层级验收：

| 阶段 | 目标 | 建议记录 |
|---|---|---|
| 软件单元测试 | 不连真机验证几何、重试、IO 状态机、参数校验 | pytest 结果、代码提交号 |
| 视觉离线回归 | 识别正确类别、中心稳定、拒绝触边/错误对象 | RGB-D、标注图、分数、误检/漏检统计 |
| 单物料吸取 | 每类物料确认可吸、可抬、可放、不会损伤 | 成功率、建压时间、压力告警、位置偏差 |
| 双竹壳交叉 | 验证角度、层间关系、运输中不缠绕 | 最终角差、位移、掉落/滑移次数 |

| 异常注入 | 人为制造未吸住、遮挡、低分、CI0 异常 | 是否安全停止、是否放气回退、是否可恢复 |
| 连续运行 | 覆盖材料批次、光照、设备温升和偶发 USB 问题 | P50/P95 节拍、MTBF、人工干预次数 |

```bash
python -m compileall -q xarm_sdk_control
```

对现场验收，不建议只报“成功几次”。至少应报告：总尝试数、每物料首抓成功率、三次内最终成功率、平均/95 分位节拍、视觉拒绝率、误抓率、压力确认超时数、相机重连数、控制器错误数、最终放置位置与角度误差。

## 16. 常见问题与处理顺序

| 现象 | 优先检查 | 不应直接做的事 |
|---|---|---|
| 视觉框中心正确，但 TCP 总偏同方向 | 先做视觉偏差悬停测量，检查 TCP 是否正确 | 直接改外参矩阵或给每个脚本加临时偏移。 |
| 相机被碰到、支架松动或画面明显歪斜 | 停止自动任务，重新固定相机并重做外参 | 只修改一个 XY bias 假装修好了。 |
| 吸盘听到漏气，CI0 不确认 | 检查 CO0/CO1 逻辑、管路、吸盘、压缩量、物料湿度与平整度 | 无限增加等待或无限增加下压。 |
| 初次确认成功但运输中掉料 | 检查吸点、载荷速度/加速度、抬升姿态、物料是否搭住料台 | 仅降低检测阈值。 |
| 竹壳被识别成荷叶或反过来 | 检查提示词、料区 ROI、物料是否完整入画、长宽比、背景光照 | 全局把置信度降到很低。 |
| 第二片竹壳找不到 | 检查第一片是否真正被移走、第二片是否露出、是否被图像边缘裁切 | 在全画面接受任意低分竹壳。 |
| 陶瓷片被压得过深，电机电流升高 | 降低陶瓷压缩量，确认深度点和陶瓷表面高度 | 用白纸/竹壳的压缩量照搬。 |
| 运动报 `code 3` | 检查实际 TCP 是否到达、状态是否为运行、错误码是否为零；代码会做有限次到位验证 | 直接忽略所有错误。 |
| 运动报 `-9` 或状态变为停止 | 检查急停、UFactory 状态、碰撞、限速/异常；先关闭真空并确保现场安全 | 立即重复运行同一命令。 |
| 预检出现 C24 | 审查关节路径和规划记录，降低速度或调整路线；当前代码将部分预检 C24 记录为告警 | 把真机真实失败也当成可忽略告警。 |
| RealSense 掉线 | 检查 USB 3.x、供电、线缆、设备枚举；代码会有限次自动恢复 | 让任务在没有新视觉帧时继续抓取。 |

在任何异常、手动中断或“可能仍吸着物料”的情况下，第一动作应是保证人员和机械臂安全，然后执行：

```bash
python xarm_sdk_control/scripts/15_vacuum_io_check.py --test off
```

之后再评估是否需要手动取下物料、解除急停、复位或重新摆料。

## 17. 开发与变更管理规范

1. 新增功能前先决定它属于视觉、路径、运动、真空、重试还是任务编排；不要把所有逻辑塞进一个脚本。
2. 改动 TCP、IO 极性、相机禁区、工作空间、压缩量、速度或重试策略时，同步更新配置、测试和本指南。
3. 每个现场参数都应有来源：实测值、传感器规格、工艺要求或重复试验结果；避免无解释的魔法数字。
4. 不要为一次失败在任务脚本中新增材料专属补丁。先判断问题属于外参、共享 bias、材料几何、末端、视觉选择还是工艺夹具。
5. 每次合格现场运行都应绑定 Git commit 与配置版本。代码、标定和工装状态三者缺一不可。
6. 新物料先写单物料 profile 和测试，再进入完整任务。通过稳定性验证后才可加入主流程。
7. 保持 `xarm_sdk_control/tests/` 可离线运行；修改安全边界、真空状态机、路径顺序、重试或解析逻辑时补对应测试。

## 18. 当前已知限制与下一阶段建议

- 荷叶还不能稳定从料台吸取，当前为预铺工艺；
- 压力开关是二值信号，无法给出连续真空度或直接判断“物料已完全离台”；
- 当前视觉偏差样本量偏少，应建立多点、多物料复验；
- 竹壳放置角含材料/吸盘滑移补偿，需要按物料状态维护；
- 当前节拍仍受到多次视觉扫描、保守速度和偶发相机重连影响；
- 工厂落地前应补充工装、物料来料一致性、连续运行统计、故障恢复 SOP 和与产线 PLC 的接口设计。

下一阶段最有价值的工作不是盲目再加速度，而是：建立标准物料工装与离线视觉回归集；采集连续真空/建立时间数据；把每类物料的最佳吸点和压缩量做成可追溯工艺配方；完成足够多次完整循环后，再用实际统计结果优化节拍。
