# 第四轮：已跑通上料流程的视觉推理实验

日期：2026-09-19。三相机定位与避障均按用户要求暂停，本轮只处理已有上料流程的检测与分割。
使用本机 RTX 4050 Laptop GPU 和 4 张历史真实 RGB-D 图像，全程未打开相机或连接机械臂。

## 环节、方法与采用状态

历史完整任务中，检测加分割是一个可重复测量的环节。我们对照了原精度、仅 SAM2 使用 BF16、
检测器与 SAM2 都使用 BF16 三种方案。BF16 自动混合精度也是
[SAM2 官方图像预测示例](https://github.com/facebookresearch/sam2#image-prediction)中的用法，
但官方用法不代表已满足本项目的抓取精度要求，必须比较输出。

**实现的是可选的“仅 SAM2 BF16”，默认仍为 float32，尚未切换实机。**

- `01_offline_grounded_sam2.py`：增加 `--sam2-precision float32|bfloat16`，仅包围 SAM2
  图像编码与掩码预测。检测器、深度值和几何运算不使用该混合精度上下文。
- `03_grounded_sam2_service.py`：增加同名启动参数，并在 ready、ping、推理响应中报告当前设置。
- `vision_result.json` 在 `sam2.precision` 中保留实际使用的设置，方便后续实验追溯。
- CPU 或不支持 BF16 的 CUDA 设备明确拒绝该实验选项，不静默切换其他精度。

结果并非完全一致，因此这一轮属于**经过离线比较的候选加速方案**，不能记为已经完成实机部署。

## 计时结果

本环境 Torch 2.13.0+cu130、RTX 4050 Laptop。每张图、每种模式单独预热，再按轮次轮换执行顺序，
重复 7 次；在阶段边界同步 CUDA，避免只测到 GPU 任务提交时间。保持原 CPU 线程配置。
白纸、陶瓷片检测阈值 0.45，竹壳 0.20，文本阈值均为 0.15。

以下是检测与分割合计的中位耗时，不含模型冷启动、采图、磁盘读写和后处理。

| 历史输入 | 原版 FP32 | 仅 SAM2 BF16 | 合计耗时减少 | SAM2 自身耗时减少 |
|---|---:|---:|---:|---:|
| 白纸，1 个检测 | 471.5 ms | 409.3 ms | 13.2% | 56.1% |
| 陶瓷片，1 个检测 | 472.0 ms | 409.1 ms | 13.3% | 56.9% |
| 竹壳，5 个检测 | 486.3 ms | 418.7 ms | 13.9% | 53.8% |
| 竹壳，7 个检测 | 499.3 ms | 427.8 ms | 14.3% | 51.5% |

四张图合计节省约 0.265 秒，仅为本批推理中位耗时相加的结果，不能写成“81 秒上料流程提速 14%”。
真实整机节拍还受到运动、规划、吸附等待和重试的影响。

## 输出变化与没有采用的方案

仅 SAM2 BF16 的 4 张图、7 次重复对照中：

- 检测数量、标签、置信度及检测框均与 FP32 基线严格一致。
- 比较前按同标签检测框进行一一匹配，显式记录未匹配目标，避免检测顺序变化造成虚假的大偏移。
- 最低掩码 IoU 为 **0.997235**，最大三维目标点差值为 **0.08194 mm**。
- 上述差值仅是两版算法在同一份深度图上的差异，不是相对实物真值的误差。
- 4 张图来自同一次历史上料，不足以证明更广泛场景下等效；尤其还要检查图像边缘截断标记、
  最终候选选择与实际吸附成功率。

检测器和 SAM2 都使用 BF16 时，合计推理约 297～319 ms，但一张竹壳图从 7 个检测变成 8 个，
正确匹配后的最大三维点差约 1.08 mm。没有把这个更快的方案加入生产入口。
早期粗比较曾按数组顺序配对，在这张图上产生约 200 mm 的虚假差异；正式报告已改为目标匹配，
同时保留新增检测，不能把错配值解释成物理定位误差。

还试探了线程数与纯 inference_mode。没有显示稳定收益，未据此修改默认配置。
线程试探中的竹壳阈值为 0.45，未覆盖生产的 0.20，因此该试探不作为生产性能结论。
这些初步脚本与结果保存在本机 `data/optimization/20260919-round4/`，正式结论以 7 次交错复测为准。

## 验证与复现

- 正式代码入口完成 4 帧 × 3 模式 × 7 次 GPU 复测，保留逐次时间、匹配指标和输出。
- 视觉环境 4 项 unittest 通过，覆盖默认模式、错误参数/CPU 拒绝、CUDA 上下文范围和恢复、输出元数据。
- 控制环境 39 项相关 pytest 通过，覆盖比较器、视觉目标处理、完整上料和单物料测试脚本。
- 原始图像、深度、已有分割结果均未被基准脚本覆盖。

[输入清单](benchmarks/vision-round4-manifest.json)和
[正式数据报告](benchmarks/vision-round4-20260919.json)可随 Git 保存。
清单引用的原始 RGB-D 位于本机 `data/`，跨机器复现需另外转移。

```bash
conda activate winejar-vision
HF_HUB_OFFLINE=1 python vision/scripts/05_benchmark_inference.py \
  --manifest docs/benchmarks/vision-round4-manifest.json \
  --output /tmp/winejar-vision-round4.json
python -m unittest discover -s vision/tests
```

输出路径必须尚不存在。基准脚本只读取历史图像，不控制硬件。
需要人工开展候选方案实验时，可在视觉服务启动命令后增加 `--sam2-precision bfloat16`；
正常原版启动命令继续采用默认 FP32。

## 下一步实验：先补上料流程数据

用户表示愿意配合实验。先确认固定全局相机、吸盘/TCP 与料台相对上次上料是否移动过；
本轮尚未得到该现场信息，没有沿用旧参数启动任何动作。

1. **静态视觉扩展集，不移动机械臂。** 白纸、陶瓷片、竹壳各至少 10 个场景，覆盖位置、朝向、
   堆叠、阴影和部分遮挡；保存 RGB、原始深度、相机参数和场景说明。对相同帧做 FP32/BF16 比较。
   记录全部新增/漏检、掩码差异、截断标记、目标选择和三维点变化。必要时增加帧清单中的阈值边缘案例。
2. **原精度完整上料计时。** 硬件状态确认后，在有人值守条件下先做 3～5 次原流程；保留每次
   `result.json`、失败和重试，不只记录成功最快的一次。重点读取新增的 `planning_diagnostics`：
   每次规划尝试、IK 调用次数与时间、回退原因、控制器预检查耗时。
3. **再决定候选方案是否实机试用。** 扩展视觉集检查通过后，用相同场景比较候选选择和吸取结果。
   小样本只能作为继续试验的依据，不能宣称生产成功率已经提高。

优先级上，解决一次 5～7 秒的规划长尾或一次抓取重试，通常比这批约 0.265 秒的推理节省更值得投入；
实际收益仍应由新的任务日志确认。
