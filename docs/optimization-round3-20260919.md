# 第三轮优化：三视图坛口拟合的重复计算

日期：2026-09-19。避障按用户要求暂不加入优化范围。本轮离线执行，没有连接设备。

## 环节与原问题

三视图坛口拟合根据俯视内口沿和两个侧视口沿，求解坛口中心、法向、内外半径。
主流程还默认进行 20 次重采样拟合，用于估计固定标定条件下的结果波动。

性能剖析发现，残差计算中重复做了以下工作：

- 每次迭代，为两个侧视相机分别生成同一条三维外圆，重复计算平面基向量、圆周三角函数。
- 投影时反复求固定相机变换的逆矩阵及旋转向量。
- 反复构造固定的圆锥曲线矩阵和观测权重，并重复计算相同的矩阵乘积。

一个带倾斜、噪声和离群点的代表案例需要约 295 次残差计算，因此单次的小开销会累积。
剖析仅用于定位函数开销；正式性能表使用未开启 profiler 的独立计时。

## 方法与代码

修改 [rim_geometry.py](../xarm_sdk_control/rim_geometry.py) 中的 `fit_multiview_rim`：

1. **单次拟合内缓存固定量：** 每台相机的逆变换、旋转向量、观测权重，以及圆周 180 点的正弦和余弦。
2. **单次迭代共享几何：** 口沿平面基向量只计算一次，两个侧视相机共用一圈三维外圆点及其参考系坐标。
3. **复用矩阵乘积：** 残差值和梯度使用同一份齐次点与圆锥曲线矩阵的乘积。

缓存只存在于一次函数调用中，不跨帧或跨标定保存。坐标转换仍按原来的
“工位坐标 → 参考相机 → 目标相机”顺序执行，以保持数值结果。

模型、鲁棒损失、权重、三个初值、参数边界、最大迭代次数、圆周采样密度及
20 次重采样数量均保留。此轮优化针对计算效率，没有修改精度验收标准。

## 性能结果

环境：Python 3.11.15、NumPy 2.4.6、SciPy 1.17.1、OpenCV 4.13.0，OpenCV 单线程。
预热后，新旧版本交替先后顺序运行 7 次，下表为中位数；只计拟合函数耗时，不含读盘、
观测提取及结果序列化。20 次重采样一行统计的是整组 20 次拟合。

| 案例 | 修改前 | 修改后 | 耗时减少 |
|---|---:|---:|---:|
| 较低倾斜，两个侧视宽度约束 | 157.33 ms | 101.66 ms | 35.4% |
| 较大倾斜，两个侧视宽度约束 | 123.52 ms | 79.55 ms | 35.6% |
| 较大倾斜，一个侧视宽度约束 | 88.74 ms | 66.90 ms | 24.6% |
| 较大倾斜，无宽度约束 | 46.10 ms | 43.45 ms | 5.8% |
| 20 次固定重采样拟合 | **16.910 s** | **10.866 s** | **35.7%，节省 6.044 s** |
| 历史真实观测，无宽度约束 | 690.29 ms | 643.78 ms | 6.7% |

有侧视宽度约束的场景收益更明显，因为需要将外圆投影到侧视图；没有宽度约束时，原本就
不执行这部分操作。20 次重采样中部分初值触及 350 次函数评估上限，导致整组耗时较长；
本轮保留这些慢样本和原来的求解上限，没有删掉慢样本或减少初值数量。

逐次耗时、数值环境、输入指纹、各初值求解记录及结果摘要见
[第三轮数据报告](benchmarks/rim-fit-round3-20260919.json)。完整逐点残差保存在本机
`xarm_sdk_control/data/optimization/20260919-round3/replay.json`。

## 如何验证

可复用脚本：[benchmark_rim_fit.py](../xarm_sdk_control/scripts/benchmark_rim_fit.py)。

- 固定随机种子生成带畸变、噪声和离群点的三视图观测。
- 覆盖低倾斜/较大倾斜，零个/一个/两个侧视宽度约束。
- 固定 20 份重采样观测，基线和新版使用同一初始拟合结果作为起点。
- 可选加载历史 `rgb_diagnostic_01/result.json` 的观测点，检查阵列指纹和地面文件哈希。
- 严格比较中心、法向、半径、逐点残差、参数标准差、条件数和触界标志。
- 比较三个初值各自的最终参数、目标函数值、状态、函数/雅可比评估次数和实际残差调用次数。

共 6 组、25 次拟合，以上结果和评估计数在本环境下均严格相等；25 次最终拟合均未触界。
这表示此次计算重用保持了测试输入的行为，不是对所有未来输入的收敛保证。

相关测试 **29 项通过，另有 2 个子测试通过**。新增了不同数量的宽度约束和调用间标定变化测试，
确认更新相机内外参后不会沿用旧的缓存。测试覆盖坛口拟合、坛口高度、观测提取、坛颈定位、
多相机标定及工位平面。

## 结果范围

本轮的真实输入来自历史诊断，侧视观测当时使用了人工种子与梯度细化。
复现时明确使用保存的拟合中心加 `[5, -4, -12] mm`，以及保存内半径的 `1.04` 倍作为
共同初值；这不是重跑当时的深度初始化或整条自动视觉流程。

历史地面仍为 `needs_metric_review`，约 476 mm 候选与用户约 250 mm 实测读数的冲突仍未解决。
提速不等于测量更准确，也不代表定位已通过现场验收；历史原始数据、标定和批准状态均未修改。
重复拟合的合计耗时也不等于完整定位流水线或机器人上料节拍。

## 复现

```bash
conda activate winejar-xarm-sdk
python xarm_sdk_control/scripts/benchmark_rim_fit.py \
  --baseline xarm_sdk_control/data/optimization/20260919-round3/rim_geometry_before.py \
  --diagnostic-result xarm_sdk_control/data/multiview_neck/jar_metric_validation_20260910/rgb_diagnostic_01/result.json \
  --output /tmp/winejar-rim-round3-replay.json

python -m pytest -q \
  xarm_sdk_control/tests/test_rim_geometry.py \
  xarm_sdk_control/tests/test_mouth_height.py \
  xarm_sdk_control/tests/test_neck_observation.py \
  xarm_sdk_control/tests/test_neck_localization.py \
  xarm_sdk_control/tests/test_multiview_calibration.py \
```

`--baseline` 会导入指定的可信本地源码快照；输出路径必须尚不存在。
不带 `--diagnostic-result` 时，只运行可独立复现的合成案例和重采样案例。
基线快照、历史诊断观测及其引用的标定/地面文件位于本机，部分在被 Git 忽略的 `data/` 下，
跨机器回放历史案例须另行携带。总体进展见[优化总记录](optimization-log.md)。
