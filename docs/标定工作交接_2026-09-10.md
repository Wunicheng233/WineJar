## 4. 无法保存的问题：已知逻辑与待验证假设

`pair_calibration_session.py` 中的流程是：

```text
read_color_pair
  -> 两路标定板检测
  -> pair_frames_fresh(timing, previous, max_pair_skew_ms)
  -> StationaryBoardGate.update(..., time.monotonic())
  -> 角点数量、分布、面积、PnP 检查
  -> 原因提示 / READY
```

当 fresh 失败时，代码把 `(None, None)` 传给静止门，静止状态立即清零。
目前窗口把时序失败和静止不足都显示为同一条等待信息，这是明确的可诊断性不足。

关键当前默认值：

| 参数 | 值 |
|---|---:|
| 连续静止时间 | 0.6 s |
| 相对静止起点的角点位移 P90 上限 | 1.0 px |
| 最大双路帧时差 | 100 ms |
| 每台最少角点数 | 20 |
| 最小角点凸包面积比例 | 0.03 |
| 最大面积比例 | 0.75 |
| 最小角点分布奇异值比 | 0.12 |
| 单目 PnP RMSE 上限 | 1.0 px |
| 与已保存姿态的最小图像位移 | 12 px |

需要按真实测量排查，以下都还不是已确认根因：

1. 双路时间差是否持续大于 100 ms，时间域是否真可比。
2. 帧号是否重复或回退，是否取到了积压帧。
3. 实际检测/GUI 循环间隔是否超过 0.6 s。当前 `StationaryBoardGate.update`
   在相邻 update 间隔大于 `max(0.3, hold_seconds)` 时重置；如果处理持续较慢，
   即使棋盘静止，也可能永远无法积累静止时间。必须先记录耗时验证。
4. 相对锚点的角点位移是否超过 1 px，是否是手抖、板面移动或检测抖动。
5. 两路可见角点集合是否频繁变化，共同角点是否少于 8。

诊断至少记录：每路帧号、设备时间戳、timestamp_domain、主机接收时间、
`skew_ms`、`skew_basis`、fresh、角点数、与锚点位移、update 间隔、重置原因。

当前 `read_color_pair` 只有在两台均为相同 global_time/system_time 域时才比较
设备时间；否则只比较主机接收时差。没有硬件同步，不能把接收时差称为曝光同步。
更不能为让它通过，简单把两台独立设备时钟当成同一个时钟。

建议让窗口分别显示“帧时差过大 / 重复帧 / 检测丢失 / 处理间隔过长 /
棋盘移动 / 正在累计静止时间”，附必要数值，以便用户知道如何调整。
保留合理的静止、质量和时序约束；通过测试与实际静止帧验证修复后，再重启采集。
