# 短颈酒坛：模型修正与首轮理想深度闭环

2026-10-22。用户明确允许在完成建模后自主开展仿真与调试。本轮完成了模型修正、
观测到目标范围的最小闭环及失败归因；没有开展完整噪声扫描，没有操作实机。

**结论：**在当前圆截面、平口沿、准确相机和无噪声深度条件下，简单半径剖面基线能够
恢复部分场景的目标几何；留出小样本中也存在约6 mm的单视图错误接受。
三视图四例全部通过当前分析阈值，只说明这个模型族/布局的有限仿真可行性。

## 模型现在表示什么

按用户照片修正为下窄上宽、上腹最宽、圆肩收至约10 mm短颈，口沿高度单独建模。
坛高约600 mm、口沿外径约125 mm、短颈约10 mm来自用户近似描述；
最大腹径360 mm、槽径105 mm、口沿高6 mm、壁厚及剖面细节仍是假设。

用户进一步纠正歪颈应是口颈一侧高、一侧低，下面基本与正常酒坛相同。
已删除会使上半坛身变弯的中心线过渡。现在只在最上方局部连接圈逐渐转动截面方向，
下面的坛身/主体肩部不变。示例倾角分量5°/-3°，约567.25 mm以下的网格与正常坛型
逐顶点完全相同；最上约32.75 mm包含连接圈、10 mm颈段和6 mm口沿。
更大倾角需要更宽的局部连接区，不能把该示例不变范围推广到所有参数。

所有截面保持圆；连接区截面方向独立于中心线切线，直颈内部二者才平行。
局部正则性检查采用`min_theta(n·c' - r ||n'||) >= 0.20`，
另检查三角形朝向和闭合壁面，不宣称证明任意形状不存在全局自交。
口部是真开口及内壁。灰白/深灰斑驳与目标位置独立，没有人工亮环。

## 实验与输入边界

4个开发场景用于调试；之后冻结估计器源码及参数，再生成4个不同高度、颈径、短颈长度、
口沿高度及轻微倾角的留出场景。两组种子分别为20261022和2026102207。
留出配置保存冻结估计器SHA-256，入口拒绝源码不匹配。现在留出结果已经分析，
这些案例不能再充当下一版方法的未见最终测试；四例也远不足以估计罕见失败率。

固定工位、每坛一组静态观测。相机固定在同一组名义布局，不随各坛目标真值移动：
640×480、50°垂直视场、约0.8 m距离；方位-50°/+50°/180°，仰角10°/10°/8°。
分别比较cam_a、cam_a+cam_b、三机，并非布局优化后的比较。
内外参为准确仿真参数；RGB和光轴Z米制float32深度共用理想针孔网格，没有虚拟板标定。

普通估计器只接收图像、深度、相机参数。固定宽工位体积裁剪Z为0.40–0.76 m、XY半径0.28 m，
不使用每坛真实高度、槽径、目标ROI或生成网格初始化。
估计结束之后评估器才读取`evaluation_only/target.json`。
新增诊断脚本明确标成oracle，可读取生成真值作归因，成绩不混入正常估计。

## 可解释的两个基线

共同先由观测最高6 mm区域提出近平向上平面候选，在较宽上部35 mm区域扩展/细化支持，
再由该平面上的点云凸包拟合口沿外圈中心。这里估计的是**口沿参考**，不是直接输出目标。

- `rim_guided_profile`：口沿平面法向作为颈轴代理，沿轴计算0.5 mm分箱的径向85%分位数，
  平滑剖面后取`r <= min(r)+1 mm`连续范围中点，输出对应三维圆心、法向及半径。
- `vertical_profile`：保持相同观测和口沿中心，但强制轴竖直，作为简单假设对照。

口沿平面与局部颈轴一致是**本轮生成模型与这个基线的共同先验**，未在实物上验证。
因此不能称为独立估计了任意坛颈法向；非平口沿、口沿与槽不平行时需要其他方法。
最高点候选策略也尚未经过深度离群点检验。

RGB前景提取只用灰/陶色低饱和度与蓝背景分离、最大连通域，不读取诊断掩码。
另列整坛可见GT掩码（含内壁），以及事后外表面GT掩码（排除内壁、不标目标圈）。
后者用于隔离结构选择误差，不是实际图像算法。没有学习模型、反复扫描或多帧平均。

少点、无近平向上平面、平面空间支持不足、剖面空档、范围碰搜索边界、候选不窄于凸唇等有拒绝原因。
目前这些是启发式质量检查，仍有错误接受；没有输出统计不确定性，平面残差不是绝对精度。

## 已查明的失败和剩余误差

1. **口沿候选误选。** 初版直接在整个上部最大化平面内点数，会选到肩部小平面。
   改成观测上包络生成候选后开发四例跑通。早期失败记录已保留，没有删除失败场景。
2. **有限视角下口沿中心偏差。** 留出`broad_reverse_tilt`单视图错误接受：圆心6.051 mm、
   直径7.482 mm。换成外表面GT掩码仍失败，说明不能仅归咎于内壁混入。
   显式oracle诊断中，只替换口沿中心后圆心误差降至0.498 mm；只替换方向仍5.609 mm；
   两者都替换为真值为0.021 mm。此例中口沿中心估计是主要误差入口。
   凸包拟圆在不完整环面上可能混入不属于外圆的边界；还需检验弧支持、候选歧义与拒绝规则。
3. **内壁和外表面不是同一证据。** 整坛GT掩码包含口内壁，某些视角会把它们混入低半径分箱，
   比RGB去掉暗内壁还差。留出`tilted_flat`双视图RGB因剖面空档拒绝，外表面GT掩码下恢复；
   这说明表面选择/提取仍是实际任务，不能用“已有掩码”跳过。
4. **范围定义的系统差异。** 平颈真值把范围限制在生成器已标注的平颈段；观测算法的宽搜索域
   会把相邻肩/唇上半径仍在1 mm容差内的部分也计入。即便用连续解析几何、无渲染或采样误差，
   两种中点仍相差0.942 mm（开发平颈）和1.051 mm（留出平颈）。这解释了部分约1 mm剩余误差。
   没有为改善成绩改动原真值。下一轮应先统一工艺搜索域和端点含义。
5. **离散与求解影响。** 其余还包含有限网格、像素采样、径向分位数、0.5 mm分箱/平滑及圆心拟合。
   当前没有逐一完成收敛/消融分析，不能把总误差全部归于其中某一项。

oracle仅作错误归因，不列入成功率。没有通过提高分辨率或按单例调整参数改善留出成绩。
三机当前四例较完整，不等于证明三机最优、单机RGB-D不可行或其他布局无效。

## 复现与后续范围

在仓库根目录，一键运行到一个不存在的新目录：

```bash
bash scripts/run_short_neck_stage1.sh experiments/neck_localization/runs/my_stage1
```

默认现有`embodied-sim`环境。新机按`experiments/neck_localization/environment.yml`建环境后，
使用`WINEJAR_SIM_ENV=winejar-neck-sim bash scripts/run_short_neck_stage1.sh ...`。
脚本执行17项有意义检查、生成两组场景、比较两方法/三视图集/两证据条件、外表面与oracle诊断、
汇总和绘图；没有连接设备的命令。输出保留全部输入/资产及`report/`小报告。
如估计器源码变化，旧留出配置的冻结散列检查会拒绝；应建立新版本及新的未见测试，不静默刷新旧散列。

下一步优先统一最细范围的物理/工艺端点，再处理有限圆弧造成的中心偏差和错误接受，
研究无需把口沿法向固定当颈轴的局部几何估计。然后才逐项引入有依据的深度偏差/空洞等扰动。
真实圆度、局部形变、釉面/红外成像及设备偏差尚未验证；本轮没有抗噪或实机精度结论。
